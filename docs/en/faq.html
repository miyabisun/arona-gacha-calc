Isn’t the chance of obtaining 2 PUs within 200 pulls using Recruitment Charge 56.34%?

The 56.34% figure assigns a fixed block of 100 pulls to each PU. If the first PU arrives early, the remaining pulls can be used for the second. Including every such path raises the exact probability to 64.09%.

What does the chart compare?

For a selected number of PUs, the chart compares the cumulative probability of obtaining all of them by each pull count under Recruitment Points and Recruitment Charge. The values are calculated exactly for every pull—not estimated by random sampling—and cross-checked with independent formulas.

What counts as obtaining a PU?

The calculation uses a 0.7% appearance rate for the targeted PU.

Does exact calculation cause a combinatorial explosion?

Recruitment Charge: First, calculate the probability that one PU is obtained on each pull from 1 through 200. Convolve that distribution once per required PU, then sum the probabilities whose total pull count is within the selected limit.

Recruitment Points: For each pull count, calculate the probability distribution of PUs obtained naturally. Add one exchangeable PU per 200 pulls, then sum the probability of meeting or exceeding the required count.

Equivalent states are aggregated instead of enumerating every pull history, so the calculation remains practical for 10 PUs and 2,000 pulls. The implementation is available in scripts/compare.js.
